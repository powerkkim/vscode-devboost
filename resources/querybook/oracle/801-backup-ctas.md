## 상황
품목 이름을 일괄로 고치기 전에, 지금 데이터를 **새 백업 테이블로 통째로 복사**해 두고 싶다. 잘못되면 백업에서 되돌린다.
백업 테이블은 아직 없다 (있으면 「백업 테이블에 쌓기」 항목).

## 예제 테이블
TB_PART (품목)

| PART_NO | REV | PART_NM |
|---|---:|---|
| P001 | 1 | 볼트 |
| P002 | 1 | 너트 |
| P003 | 1 | 와셔 |

## 원하는 결과
TB_PART_BK_20261109 (새로 생긴 백업 테이블)

| PART_NO | REV | PART_NM | BK_DT |
|---|---:|---|---|
| P001 | 1 | 볼트 | 2026-11-09 14:30:00 |
| P002 | 1 | 너트 | 2026-11-09 14:30:00 |
| P003 | 1 | 와셔 | 2026-11-09 14:30:00 |

## 쿼리
```sql
CREATE TABLE ${백업테이블:TB_PART_BK_20261109} AS
SELECT t.*, SYSDATE AS BK_DT
  FROM ${테이블:TB_PART} t
 WHERE ${조건:1 = 1}
```

## 풀이
- `CREATE TABLE 새이름 AS SELECT …` = SELECT 결과로 테이블을 만들고 데이터까지 한 번에 넣는다.
- `SYSDATE AS BK_DT` 로 언제 백업했는지 칸을 하나 더 붙였다. 필요 없으면 `SELECT * FROM 테이블` 로.
- 일부만 백업하려면 조건 자리에 `PART_NO LIKE 'P0%'` 처럼. 구조만 복사하려면 `WHERE 1 = 0`.
- **주의 1 — 자동 커밋**: CREATE TABLE 은 DDL 이라 실행하는 순간 그 세션에서 **커밋하지 않은 변경까지 함께 커밋**된다. 백업은 다른 작업 전에, 깨끗한 상태에서 먼저 한다.
- **주의 2 — 따라오지 않는 것**: NOT NULL 만 복사되고 PK·인덱스·기본값·주석·권한은 복사되지 않는다. 백업용으로는 충분하지만, 같은 모양의 운영 테이블을 만들 때는 DDL 을 따로 쓴다.
- 이름에 날짜를 붙여(`_BK_20261109`) 언제 것인지 알게 하고, 다 쓰면 `DROP TABLE 백업테이블 PURGE` 로 지운다.
- 큰 테이블은 `CREATE TABLE … NOLOGGING AS SELECT` 가 빠르다 (DBA 와 상의 — 복구 로그가 남지 않는다).
- 데이터를 만드는 문장이라 연습 실행은 없다. 실행 뒤 `SELECT COUNT(*) FROM 백업테이블` 로 건수를 원본과 비교한다.

## 바꿔 쓸 곳
- 되돌리기는 「백업 테이블 값으로 되돌리기」 항목
