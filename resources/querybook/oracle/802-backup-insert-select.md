## 상황
이미 만들어 둔 백업(이력) 테이블이 있다. 고치기 전마다 **지금 행들을 그 테이블에 이어서 쌓아** 두고 싶다. 언제·왜 백업했는지도 함께.
다른 테이블로 데이터를 옮길(이관) 때도 같은 모양이다.

## 예제 테이블
TB_PART (원본)

| PART_NO | REV | PART_NM |
|---|---:|---|
| P001 | 1 | 볼트 |
| P002 | 1 | 너트 |
| Q100 | 1 | 핀 |

TB_PART_BK (백업, 칸이 두 개 더 있다: BK_DT 백업일시, BK_REASON 사유) — 처음엔 비어 있음

## 원하는 결과
조건(`PART_NO LIKE 'P0%'`)에 맞는 2행만 TB_PART_BK 에 들어간다

| PART_NO | REV | PART_NM | BK_DT | BK_REASON |
|---|---:|---|---|---|
| P001 | 1 | 볼트 | 2026-11-09 14:30:00 | 일괄수정 전 백업 |
| P002 | 1 | 너트 | 2026-11-09 14:30:00 | 일괄수정 전 백업 |

## 쿼리
```sql
INSERT INTO ${백업테이블:TB_PART_BK} (${칸목록:PART_NO, REV, PART_NM}, BK_DT, BK_REASON)
SELECT ${칸목록}, SYSDATE, '${사유:일괄수정 전 백업}'
  FROM ${테이블:TB_PART}
 WHERE ${조건:PART_NO LIKE 'P0%'}
```

## 풀이
- `INSERT INTO 대상 (칸들) SELECT …` = SELECT 결과 행들을 그대로 대상 테이블에 넣는다. VALUES 대신 SELECT 가 온다.
- 넣는 칸 목록을 **꼭 적는다**. `INSERT INTO 백업 SELECT * FROM 원본` 은 두 테이블의 칸 순서·개수가 완전히 같아야 하고, 나중에 원본에 칸이 추가되면 바로 오류가 난다.
- 먼저 같은 조건으로 `SELECT COUNT(*) FROM TB_PART WHERE …` 를 돌려 몇 건이 들어갈지 보고, 실행 결과의 "n행" 과 맞는지 확인한 뒤 **커밋**한다 (콘솔은 자동 커밋하지 않는다).
- 사유·일시 칸을 두면 같은 품목을 여러 번 백업해도 언제 것인지 구분된다. 되돌릴 때는 `BK_DT` 가 가장 최근인 것을 쓴다.
- 대량이면 `INSERT /*+ APPEND */ INTO …` 가 빠르다 (그 테이블은 커밋 전까지 같은 세션에서도 다시 읽을 수 없다).
- 데이터를 바꾸는 문장이라 연습 실행은 없다.
